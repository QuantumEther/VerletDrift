# WebGPU laboratory integration

PERFORMANCE_2 now has a genuine renderer selector in the existing laboratory. It reloads explicitly, resetting the experiment. `?backend=webgpu` requests WebGPURenderer; initialization verifies the backend and never silently selects WebGL. Default and `?backend=webgl` preserve the WebGL path. Native device loss is surfaced as a fault. Raw WebGL-clear diagnostics are explicitly unavailable on WebGPU, and WebGL timer-query measurements are not represented as GPU measurements there.

The existing scene, controls, physical state, vehicle assets and audio are reused. Standard/physical vehicle materials use Three's node-renderer conversion. Tracks, contact shading, distributed cloud shadows, terrain palette/detail/roughness/bump and authored corridors/road markings have TSL paths. Smoke uses instanced billboards sharing the existing particle arrays; HDR sampling was ported to the TSL shader. HDR decode is shared and environment prefiltering uses WebGPU's PMREMGenerator. Backend selection is experimental: exact material/noise/transparency/shadow parity has not been established, and no measured performance benefit is claimed.

## Launch and validation

Serve the repository root with `python3 -m http.server 8000`, open `http://localhost:8000/research/scientific-rebuild/fast-vehicle-poc/variable-terrain/laboratory/`, and use Renderer to select WebGL or WebGPU. Native presentation must be tested on a compatible desktop GPU/browser. This cloud has no DISPLAY, Xvfb or xvfb-run. Earlier raw-canvas tests reproduce its presentation failure independently of Three.js; we stopped changing browser flags/shaders to address that infrastructure problem.

For GPU rendering validation without native presentation, append `?backend=webgpu&presentation=offscreen`. This renders the actual laboratory into a GPU texture; its ordinary canvas is not a replacement presentation path. `rendererReadback()` returns packed-stride metadata and GPU pixels for tests. It does not introduce an ongoing CPU readback loop or claim interactive offscreen display performance.

`node research/scientific-rebuild/fast-vehicle-poc/variable-terrain/laboratory/live-webgpu-browser.mjs` selects the actual Schweinemotorwerke GLB, verifies WebGPU, captures GPU texture readback and writes `results/live-webgpu.{json,png}`. Baseline captures succeeded for the reference and custom vehicle; loaded HDR decoding/prefiltering reported ready. A fuller Balanced run and a WebGPU run switching from automatic/full to 50% resolution did not finish within the bounded investigation and were stopped; the cause remains unresolved, so resolution switching is not claimed verified. The script now bounds readback to 15 seconds and accepts `--balanced` for that unresolved test. It does not claim native screen-presentation success. `tsl-terrain-browser.mjs webgpu` compiled the authored road path with pixel readback; `tsl-smoke-browser.mjs webgpu` compiled the updated HDR-sampling shader in its controlled fixture.

The final Node suite executed 33 passing tests. WebGL responsive browser checks passed after integration; the serialized-reset path also passed its three-size browser check. Full backend switching/disposal under load, all quality presets, moving-vehicle WebGPU contact/slip scenarios, audio on the WebGPU path, matched WebGL/WebGPU image differences and hardware timing remain unverified. No parity, 240 FPS, or performance speedup claim is justified by these captures.

The final capture helper also accepts `--webgl` for an offscreen WebGL comparison. It uses explicit full resolution by default (`--half` selects 50%) and flips WebGL's bottom-up rows. Target sizing is independent of native buffer sizing; targets are rebound after resize so empty textures cannot pass. It rejects fully transparent readbacks. The readback overlay preserves the running application's DOM; the helper's earlier DOM-replacement page error was corrected. Renderer initialization is serialized across rapid resets, and stale initialization errors do not fault a newer view. The historical diagnostic field named `webgl` still records CPU submission time, not GPU execution time, on either backend.

## Baseline image comparison

`results/live-backend-comparison.json` records the completed resting custom-vehicle comparison: both render targets 526×329, render scale 1, matching camera, screenshot sizes 800×501. Mean absolute 8-bit RGB differences were [0.01916, 0.01150, 0.02010]. This supports close output agreement for this Baseline scene only. Background pixels dominate a global mean; it does not certify per-material, HDR, smoke, transparency or dynamic parity. No frame-rate improvement was inferred.
