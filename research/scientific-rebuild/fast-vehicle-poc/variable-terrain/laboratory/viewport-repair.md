# Viewport and smoke availability verification

The inherited three-column layout and fixed 510 px canvas height left a narrow, tall driving view at intermediate browser widths. Camera resizing also occurred after the scene-update early return and only updated the projection when the rounded drawing-buffer size changed. The lab now uses a local 16:10 canvas, two columns below 1200 px and one below 760 px. Camera projection tracks CSS aspect independently of buffer changes, including when scene transformations are disabled. Vehicle geometry and physics were not changed.

Tire Smoke is expanded by default. All five sliders are present: amount 0–500%, opacity, size/expansion, lifetime and dispersion. The existing scripts exercise maximum settings through actual DOM input events. No caching or deployment fault has been established. A branch push does not itself establish the deployed GitHub Pages revision; the standalone lab path is `research/scientific-rebuild/fast-vehicle-poc/variable-terrain/laboratory/`.

Executed: 33 Node tests passed (`node --test research/scientific-rebuild/fast-vehicle-poc/variable-terrain/laboratory/*.test.mjs`). `viewport-browser.mjs` passed at 1440×1000, 1000×800 and 600×900, verifying CSS ratio and visible/open control markup. Screenshots and buffer metadata are in `results/viewport-*`. The real-physics `intense-tire-smoke-scenarios-browser.mjs` passed normal rolling with zero emission, braking, lateral sliding/handbrake and dirt dust after the layout change. New captures are `results/viewport-smoke-*`; previous `intense-smoke-*` captures are preserved as comparisons.

The previous maximum-setting stationary burnout capture remains `results/intense-smoke-stationary.png`; it was not rerun during this layout repair. The low/high visual-control comparison remains covered by the Node smoke test, not a new matched browser image pair. Tests used Chromium/SwiftShader, not RTX hardware. No attached screenshot was accessible in this request, so its exact browser conditions could not be reproduced. The changes address the demonstrated layout/resizing weaknesses; no unsupported claim is made about browser zoom or a particular user's deployed cache.
