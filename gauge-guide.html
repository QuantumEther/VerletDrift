Part 1: Canvas Fundamentals for Beginners

🤔 Why Can't F12 DevTools Edit Canvas Gauges?

The simple answer: Canvas is immediate-mode pixel drawing, not retained DOM elements.

🔹 Immediate-Mode vs Retained-Mode

DOM Elements (retained-mode):
  • Browser stores each element as a persistent object
  • You can query and modify them anytime: element.style.color = 'red'
  • Browser automatically re-renders when you change properties
  • DevTools can inspect these objects in real-time
Canvas Drawings (immediate-mode):
  • Canvas just has a 2D context with drawing methods: ctx.fillRect(), ctx.arc(), etc.
  • When you call a drawing method, it immediately paints pixels to the canvas
  • Once drawn, canvas has no memory of what was drawn—it's just colored pixels
  • To update a gauge, the entire canvas must be erased and redrawn from scratch next frame
  • DevTools cannot select or inspect drawn shapes because they don't exist as DOM objects

What CAN DevTools Inspect?

✅ The canvas element itself:
  • Right-click → Inspect to see <canvas id="rpmCanvas" width="900" height="780"> in the DOM
  • Read/edit CSS properties: width, height, display, position
  • Inspect the 2D context: document.getElementById('rpmCanvas').getContext('2d')
✅ JavaScript values controlling the gauge:
  • Console → type state.engine.rpm to read current RPM
  • Read needle positions, speed, acceleration, etc.
  • Watch state values update in real-time as you drive
❌ CANNOT do:
  • Click element picker to select and highlight a drawn gauge
  • Right-click on the red zone to change its color
  • Edit canvas pixel content directly from DevTools

How Canvas Drawing Actually Works

// Frame 1: Draw the gauge
const ctx = rpmCanvas.getContext('2d');
ctx.fillStyle = '#f5f0e8';        // Set fill color
ctx.beginPath();
ctx.arc(450, 390, 200, 0, Math.PI * 2);  // Draw a circle
ctx.fill();                       // Paint it to canvas

// Frame 2: ERASE and REDRAW
ctx.clearRect(0, 0, 900, 780);    // Clear entire canvas
// ... redraw the entire gauge again with new needle position ...

// Key insight: The circle from Frame 1 is GONE
// Canvas doesn't remember it existed—it's just pixels

The Implication

To change how a gauge looks, you MUST edit the source code (or use the browser console to override values). There's no "click and edit" shortcut like you'd use for DOM elements.

Part 2: The Three-File Gauge System

All gauge changes flow through exactly three files. Understanding which file to edit is the key to becoming efficient.

js/constants.js ───┐ ├──→ js/main.js (drawGauges) js/ui.js ───┤ ↓ ├──→ js/renderer.js (drawAnalogGauge) │ ↓ └──→ Canvas (pixels)
File What It Stores When to Edit Example Change
constants.js Tunable parameters (max RPM, max speed, physics constants) Display ranges, thresholds, speeds TACHOMETER_REDLINE_RPM = 5500
main.js Gauge configuration created each frame in drawGauges() Per-gauge visual settings (labels, tick spacing) majorStep: 30 in speed config
renderer.js Low-level canvas drawing functions Colors, gradients, needle shape, text styling Gradient colors in _getGaugeGrads()

Edit Strategy: Priority Order

1️⃣ Edit constants.js FIRST if possible
  • ✅ Easiest: one-line changes
  • ✅ No side effects or complex logic
  • ✅ Changes flow automatically to all gauges that use the constant
2️⃣ Edit main.js SECOND
  • ✅ Isolated to one gauge at a time
  • ✅ Clear cause-and-effect: change majorStep, ticks change
  • ⚠️ Slightly more complex (config objects, functions)
3️⃣ Edit renderer.js LAST
  • ⚠️ Changes affect ALL gauges unless you add conditional logic
  • ⚠️ Low-level drawing code requires understanding canvas APIs
  • ✅ Direct control over visual appearance

The Edit Workflow

  1. Identify what to change: Is it a range? A color? A label format?
  2. Determine the file: Use the priority order above
  3. Make the change: Edit the file in VS Code (or your editor)
  4. Save: Ctrl+S
  5. Hard-refresh browser: Ctrl+Shift+R (not just F5)
  6. Verify visual result: Does the gauge look as expected?
  7. Iterate: If not right, re-edit and hard-refresh
⚠️ Hard-Refresh is Critical
Regular refresh (F5) may load JavaScript from the browser's module cache, showing old code. Hard-refresh (Ctrl+Shift+R) clears the cache and forces a fresh download of all modules.

Edit 1: Change RPM Redline from 6500 to 5500 RPM constants.js

What You're Doing

Move the red "danger zone" on the RPM gauge to start at 5500 RPM instead of 6500 RPM. This is a one-line change in constants.js.

Step-by-Step

  1. Open js/constants.js in your editor
  2. Find line ~42: export const TACHOMETER_REDLINE_RPM = 6500;
  3. Change 6500 to 5500
  4. Save the file (Ctrl+S)
  5. Switch to browser and hard-refresh (Ctrl+Shift+R)
  6. Open simulator and accelerate to watch the red zone appear earlier

Code Diff

Before
export const TACHOMETER_REDLINE_RPM = 6500;
After
export const TACHOMETER_REDLINE_RPM = 5500;

Visual Result

Expected behavior:

  • At idle (~500 RPM): No red zone visible
  • At 5400 RPM: Red arc just starts appearing
  • At 8000 RPM: Needle deep in the red zone
  • The red zone is now narrower (5500–10000 RPM instead of 6500–10000 RPM)

Live Preview

BEFORE: Redline at 6500
AFTER: Redline at 5500

Both gauges showing 7000 RPM. Notice the red zone starts earlier in the "After" version.

Why It Works

Here's the code path:

  • main.js line 922: drawAnalogGauge(..., redFrom: TACHOMETER_REDLINE_RPM) — passes the constant to the drawing function
  • renderer.js line 1459: if (config.redFrom !== null) { /* draw red arc */ } — checks if redline is set
  • The red arc is drawn from redFrom to max of the gauge
  • Needle position scales linearly: angle = startAngle + sweepAngle * (rpm / TACHOMETER_MAX_RPM)

Test Verification

  • ☐ Idle test: Start sim, don't accelerate. No red zone at ~500 RPM.
  • ☐ Threshold test: Accelerate to 5500 RPM. Red zone just starts appearing.
  • ☐ High RPM test: Accelerate to 8000 RPM. Needle deep in red.
  • ☐ Comparison: Red zone is now narrower than before (visual confirmation)

Live Preview

BEFORE: 0–400 km/h, step=20
AFTER: 0–300 km/h, step=30

Both showing 150 km/h. Notice the "After" version uses the full gauge width, making the needle more readable.

Why It Works

Tick mark generation logic in renderer.js (line 1395):

for (let val = config.min; val <= config.max; val += config.majorStep) {
  // Draw label at val
}

With min=0, max=300, majorStep=30, this generates labels at: 0, 30, 60, ..., 300.

Minor ticks are spaced as majorStep / minorDivisions = 30 / 5 = 6 km/h.

Part 3: Browser Console Debugging & Runtime Inspection

Why Use the Console?

DevTools' Element Inspector can't edit canvas, but the Console is a JavaScript REPL where you can:

  • Read live state values in real-time
  • Test changes without editing files
  • Debug gauge physics and rendering
  • Monitor values over time

How to Access the Console

  1. Open the simulator in your browser
  2. Press F12 to open DevTools
  3. Click the Console tab (not Elements/Inspector)
  4. Type JavaScript commands directly

Common Inspections

All vehicle state is stored in state object (exported from state.js).

Commands:

// Current RPM
state.engine.rpm

// Current speed (m/s)
state.body.speed

// Speed in km/h (convert from m/s)
state.body.speed / 0.27778

// Lateral acceleration (m/s²)
state.body.lateralAccel

// Engine running / stalled?
state.engine.isRunning
state.engine.isStalled

// Engine throttle (0–1)
state.engine.throttleInput

Example Output:

> state.engine.rpm
6200

> state.body.speed / 0.27778
95.2

> state.engine.isRunning
true

To inspect needle spring physics, you first need to expose the needle objects globally. Add this to main.js after line 234:

// For console debugging
window.rpmNeedle = rpmNeedle;
window.speedNeedle = speedNeedle;
window.latGNeedle = latGNeedle;

Then in the console:

// Read current needle position (0–1 normalized)
window.rpmNeedle

// Output: Object with internal state
Object {
  currentNeedlePosition: 0.62,
  currentNeedleVelocity: 0.015,
  elapsedSeconds: 12.4
}

// Just the position
window.rpmNeedle.currentNeedlePosition
// Output: 0.62

// Check if needle is fluttering (moving above threshold)
window.rpmNeedle.currentNeedlePosition > 0.80
// Output: true (if RPM > 80% of max)

Read and inspect the canvas drawing context:

// Get the RPM canvas element
const rpmCanvas = document.getElementById('rpmCanvas');

// Get its 2D context
const rpmCtx = rpmCanvas.getContext('2d');

// Check canvas dimensions
rpmCanvas.width    // 900
rpmCanvas.height   // 780

// Read current canvas state
rpmCtx.fillStyle        // current fill color
rpmCtx.strokeStyle      // current stroke color
rpmCtx.lineWidth        // current line width
rpmCtx.font             // current font

// Check if canvas is in a specific state
rpmCtx.fillStyle === '#e0e0e0'  // is it light grey?

Use case: Test a change without editing source code.

Limitation: This only works if the constants are imported and stored as module-level variables. Many times, the constants are "baked in" at module load time, so runtime changes won't affect them.

If the constant is imported globally:

// In main.js, constants are imported like:
// import { TACHOMETER_REDLINE_RPM } from './constants.js'

// You can try to override it (may not work):
TACHOMETER_REDLINE_RPM = 5000;

// Then force a redraw (requires drawGauges to be exposed)
window.drawGauges(0.016);

Better approach: Edit the source file and hard-refresh. Runtime overrides are experimental and often don't work as expected due to how ES6 modules cache imports.

Create a logging loop that prints values every 0.5 seconds:

// Log RPM and speed every 500ms for 10 seconds
const interval = setInterval(() => {
  const speedKph = (state.body.speed / 0.27778).toFixed(1);
  console.log(`RPM: ${state.engine.rpm}, Speed: ${speedKph} km/h`);
}, 500);

// Stop after 10 seconds
setTimeout(() => clearInterval(interval), 10000);

Expected Output:

RPM: 1200, Speed: 0.0 km/h
RPM: 1500, Speed: 2.3 km/h
RPM: 2100, Speed: 5.8 km/h
RPM: 3400, Speed: 12.1 km/h
(... more lines ...)

Advanced Tips & Best Practices

🎯 Canvas Debugging Patterns

If gauge colors don't look right, verify the gradient was created:

// In browser console:
const ctx = document.getElementById('rpmCanvas').getContext('2d');

// Create a test gradient
const grad = ctx.createRadialGradient(150, 150, 0, 150, 150, 200);
grad.addColorStop(0, '#1a1a1a');
grad.addColorStop(1, '#3a3a3a');
ctx.fillStyle = grad;

// Check if fillStyle is the gradient object
ctx.fillStyle === grad  // true if gradient set

If your changes don't appear, there may be a JavaScript error preventing the page from loading new code:

  1. Press F12 → Console tab
  2. Look for red error messages
  3. Read the error message and line number
  4. Common errors:
    • SyntaxError: unexpected token — typo in your edit
    • ReferenceError: undefined variable — misspelled variable name
    • TypeError: cannot read property of undefined — trying to use something that wasn't initialized

Before making a big change, test it on a dummy canvas first:

// Create a test canvas
const testCanvas = document.createElement('canvas');
testCanvas.width = 300;
testCanvas.height = 300;
document.body.appendChild(testCanvas);

const ctx = testCanvas.getContext('2d');

// Try your drawing code
ctx.fillStyle = '#1a1a1a';
ctx.fillRect(0, 0, 300, 300);
ctx.fillStyle = '#e0e0e0';
ctx.font = '20px Arial';
ctx.fillText('Test', 150, 150);

// Check if it looks right before applying to actual gauges

⚡ Performance Tips

  • Cache gradients: Creating gradients is expensive. The code already caches them in a WeakMap. Don't recreate them every frame.
  • Limit redraws: Only redraw canvases that have changed values.
  • Use requestAnimationFrame: The main loop is already set up correctly; don't add extra redraws.

🔧 Troubleshooting Checklist

Changes not appearing?
  1. ☐ Did you save the file? (Ctrl+S)
  2. ☐ Did you hard-refresh? (Ctrl+Shift+R, not just F5)
  3. ☐ Are there console errors? (F12 → Console)
  4. ☐ Did you edit the correct file?
  5. ☐ Did you edit the correct line?
  6. ☐ Did you use the exact constant/variable names?
  7. ☐ If still stuck, try:
    • Restart dev server: Ctrl+C, then python3 serve.py
    • Close and reopen browser
    • Clear browser cache (Ctrl+Shift+Delete)
