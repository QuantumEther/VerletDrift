Overview & Architecture

The Problem

VerletDrift's original logging system was scattered across 7 files with ~20 console calls creating continuous noise that buried useful signals:

Original Architecture (Fragmented): ┌─────────────────────────────────────────────┐ │ Scattered console.log/warn/error calls │ │ - 2 per-frame UI updates │ │ - 2 per-substep engine logs │ │ - No central control │ │ - No event history │ │ - No telemetry visibility │ └─────────────────────────────────────────────┘ ↓ Per-frame console spam No debugging context No temporal correlation

The Solution

A unified observability system with DebugController as the authoritative source, structured event buffer for history, and real-time overlay telemetry.

New Architecture (Centralized): ┌────────────────────────────────────────────────┐ │ DebugController (Config) │ │ ┌──────────────────────────────────────────┐ │ │ │ - Level: silent/quiet/info/debug/verbose│ │ │ │ - Overlays: enabled/disabled │ │ │ │ - Trace: channel + duration │ │ │ │ - Freeze: on error mode │ │ │ └──────────────────────────────────────────┘ │ └────────────────────────────────────────────────┘ ↓ ↓ ↓ Logger EventBuffer Telemetry (Channels) (History) (Overlay) (Gating) (200 events) (Real-time) (Sampling) (Deduplication) (F2/F3 control)

Phase 3: Event Enrichment

Timeline: 1.5 hours | Status: COMPLETE

The Problem

Events had frame and tSimSec fields but always defaulted to 0 because callers never populated them. This prevented temporal correlation of events.

The Solution

Automatic event enrichment at the API boundary using lazy state reference initialization:

// events.js - Auto-inject at push time
export function pushEvent(eventData) {
  return {
    ...eventData,
    tSimSec: eventData.tSimSec ?? (stateRef?.loop?.simulationTime ?? 0),
    frame: eventData.frame ?? (stateRef?.debug?.frame ?? 0),
  };
}

Benefits

✅ Zero breaking changes (optional chaining with defaults)

✅ Works in test environments (fallbacks to 0)

✅ No circular dependencies

✅ 22 callsites unchanged

✅ Events now temporally correlated

Phase 6: Event Optimization

Timeline: 1.5 hours | Status: COMPLETE

The Problem

2x Event Duplication for critical faults:

Example: Constraint Spike
Event 1: { type: 'log_warn', msg: 'Constraint spike: 0.1234m' }
Event 2: { type: 'constraint_spike', msg: 'Constraint spike: 0.1234m' }

Same information recorded twice = wasted buffer space

The Solution

Suppress generic log events for semantic channels in logger.js:

const semanticChannels = new Set(['fault', 'wheels', 'drivetrain', 'smoke']);
const isSemanticChannel = semanticChannels.has(channel);

if (eventRingBuffer && (level === 'warn' || level === 'error') && !isSemanticChannel) {
  eventRingBuffer.pushEvent({...}); // Only if NOT semantic
}

Event Buffer Improvement

Scenario Before After Improvement
10 spikes + 5 drops + 3 runaways 54 events (27% buffer) 18 events (9% buffer) 3x more room

Phase 7: State Consolidation

Timeline: 0.5 hours | Status: COMPLETE

The Problem

Two deprecated fields kept in sync with DebugController but never read:

  • mode: 'quiet' — WRITE-ONLY, never read from
  • overlaysEnabled: boolean — WRITE-ONLY, never read from

Every F2/F3 press required syncing 2 fields—maintenance burden with zero benefit.

The Solution

Remove deprecated fields entirely, use controller directly for all queries.

Final state.debug Structure

state.debug = {
  controller: DebugController,              // Single source of truth
  frame: 0,                                 // Frame counter
  metrics: { dtMs, constraintMaxCorr, ... }, // Pure measurements
  transitionState: { ... },                 // Event detection state
  events: EventBuffer,                      // Ring buffer
  faults: { freezeOnError, isFrozen },     // Fault state
}
// 9 fields (down from 11), zero redundancy ✓
