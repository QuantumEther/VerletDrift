The inventory is dependency-aware, not an assertion that every shader/source line was audited. Boundary implementation was located through its exported function in `constraints.js`. Presentation A entries keep their implementation where the adapter supplies the existing inputs; whole modules with shared-state access remain B.

Migration order: commands/config → isolated core → versioned snapshots/telemetry → drivetrain ports → event adapters → opt-in integration. Do not replace the recovery app while those seams remain untested. Architecture tests must prove visuals cannot alter mechanics, renderer rate does not change command assignment, and changing effects/RNG does not change trajectories. Preserve historical free-motion, input-release, rendering ownership, artwork and manual driving tests as fixtures; do not force new dynamics to reproduce known physical errors.
