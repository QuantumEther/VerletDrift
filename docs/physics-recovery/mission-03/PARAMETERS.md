# Steering parameters and compatibility

All torque/inertia quantities below use the common **road-wheel** coordinate. No graphics control or layout changed. There are no additional sliders.

| Setting / ID | Default | Supported UI range | Units | Classification and dependencies |
| --- | ---: | --- | --- | --- |
| Center Spring / Inertia (`steeringSelfCenterRate`) | 5 | 0–30 | s⁻² | Empirical mechanical approximation, k/I. k = I×setting; now fixed at all speeds. Zero disables. Not a rate controller or caster calibration. |
| Road-Wheel Inertia (`steeringColumnInertia`) | 0.08 | 0.01–1 | kg·m² | Effective physical configuration, uncalibrated. Includes both fronts in the common coordinate. Changing it also changes normalized centering stiffness and driver impedance. |
| Viscous Damp (`steeringViscousDamping`) | 5.5 | 0–10 | N·m·s/rad | Passive mechanical approximation; opposes road-wheel rate. Exact affine interval integration. |
| Coulomb Friction (`steeringCoulombFriction`) | 0.05 | 0–2 | N·m | Equal static capacity / sliding torque. Bounded impulse and exact subthreshold hold. No separate coefficients without calibration. |
| Pneumatic Trail (`pneumaticTrail`) | 0.035 | 0–0.2 | m | Tire empirical configuration. Same Mission 02 law, combined-slip decay and signed transport. Not caster or static scrub. |
| Max Steer (`maxFrontWheelAngle`) | 0.52 | 0.1–1.2 | rad | Symmetric common-angle unilateral stops. Also maps visual/input range; live reduction is an explicit intervention. |
| Steer Drag Range (`steeringDragRange`) | 150 | 50–400 | px | Input-control sensitivity: relative travel for one visual lock amplitude. Drag anchors at current angle. |

Scale must not be inferred from the old “Column Inertia” name. If the default visual ratio 15.104 were used as a real ideal gear ratio, Iδ=0.08 would imply a handwheel inertia of only 0.000351 kg·m², bφ≈0.0241 N·m·s/rad and Cφ≈0.00331 N·m. These are algebraic implications, not measured hardware values or a claim of realistic calibration. The existing effective coordinate is made explicit instead of multiplying parameters by an assumed real ratio. Hardware identification of ratio, reflected inertia, damping and friction is needed before interpreting this model as a particular vehicle; no such parameter changes were made to improve stability or speed.

Hidden values are no longer disguised as physical hardware: driver natural frequency 40 s⁻¹ and critical unloaded damping specify input response; visual lock 2.5π rad specifies HUD/input mapping. Neither is an extra tire-force multiplier. Adaptive steering comparison bounds are numerical parameters, not vehicle controls: angle 1e-7 rad + 1e-4 relative, rate 1e-5 rad/s + 1e-4 relative. Original contact accuracy thresholds and depth limit remain unchanged. Analytic evaluation uses an 18-term short-interval series below dimensionless rate×step 0.1, three-point diagnostic quadrature below 0.001, 60 bisections per event, and a 128-event guard that requests subdivision on exhaustion. These are numerical safeguards, not physical steering gains or hidden assistance.

Derived quantities include `k=I×rate`, unloaded column `ω_n=sqrt(k/I)`, `ζ=b/(2sqrt(Ik))` for k>0, driver gains, and the visual ratio. Default stationary no-driver `ω_n=sqrt(5)=2.236 s⁻¹`, `ζ≈15.37`: strongly overdamped, not a default critical damper. With C>0, linearization only describes sliding portions; static hold is a nonsmooth equilibrium set. Tests deliberately include underdamped, critical and overdamped configurations. At stationary default settings the static spring/friction equilibrium band is |δ|≤C/k=0.125 rad (about 7.16°); that off-center hold is not a visual dead zone. Not every physically allowed setting must suppress oscillation.

Read-only diagnostics are angle/rate/acceleration/jerk, steering work ledger, stop/friction impulses, body sleep intervention, and solver residual/iteration/subdivision counters. The old rate gate, previous-tick production SAT input and speed-faded restoring assistance are retired mechanisms.

Exports retain configuration version 2 and tire model identity, adding `steeringModelVersion:1`. Existing field IDs, numerical values, ranges and road-wheel units remain valid. Old/unversioned steering imports explicitly announce the changed fixed-spring and finite-driver semantics. This is intent/parameter compatibility, **not preservation of the former speed-faded trajectory or direct position override**. Unsupported steering model versions are rejected atomically. Built-in presets retain their numerical values. An old preset may now hold off-center under static friction, retain a small high-speed mechanical spring, and have finite input response.

Programmatic drivers should set `steering.isDragging=true` and `steering.targetWheelAngle` (visual-coordinate target), or invoke the pure mechanics API with a prescribed external torque. Initial legacy `wheelAngle` assignment is captured when dragging starts without a target; subsequent changing targets belong in `targetWheelAngle`. Rendering owns the actual HUD angle. Release sets `isDragging=false`; do not zero the physical angular velocity. Historical scripts that repeatedly overwrite the old HUD field need this explicit input-interface update.
